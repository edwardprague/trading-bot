Workflow & Methodology

The Discovery → Version → BD/RA pipeline, development rules, testing approach, and git hygiene.

Dashboard Workflow
1

Run Discovery

Set instrument, interval, direction, blocked hours. Run 200+ trials over a training window. Review passing trials sorted by PF.

2

Assign to Version

Click Assign on a promising trial. This creates a version profile with all parameters locked. data/versions.json is the source of truth — commit after changes.

3

Validate on BD (out-of-sample)

Run the version on a date range Discovery never saw. Check whether numbers degrade gracefully or collapse. Accurate P&L — don't re-run sub-periods, read from the parent run's tables.

4

Confirm on RA

Check that regime gates make intuitive sense on the out-of-sample window. Are the blocked regimes genuinely bad, or overfitting to training noise?

5

Generate cBot & Forward Test

Click Create cBot on the BD. Copy FractalBot_v{N}.cs into cTrader. Run on live data. Edit logic in cbot_templates.py, not the generated file.

💡
Discovery is the source of truth for all strategy parameters. Parameters flow Discovery → Version → BD/RA. Nothing downstream should override instrument, interval, or direction.
Development Rules
  • New styling goes in style.css — never inline style="…" on new HTML. Legacy inline styles in INJECT_HTML are grandfathered.
  • Strategy template duplication — strategy_v1.py and strategy_v2.py each carry their own copy of report.html's structure. Any change to the inline JS or markup must be applied to both templates.
  • Never edit report.html directly — it is auto-generated and will be overwritten on the next backtest run.
  • Task completion — always state what needs to happen to see the change: restart Flask, run a backtest, run python3 regime_analysis.py, or a combination.
  • In-browser verification — visual and event-flow bugs must be verified in a real browser via Claude in Chrome, not just sandbox-tested.
  • RRR cached constant bug — strategy_v2.py computes RRR once at import. When overriding params in-process, always recompute: strat.RRR = float(strat.RRR_REWARD) / float(strat.RRR_RISK)

Testing Approach

  • computer(action='screenshot') — see current state
  • javascript_tool — read DOM state, check scroll positions, verify data
  • computer(action='type', text='2') — trigger keyboard shortcuts (click page body first)
  • computer(action='wait', duration=N) — max 10s between polling for long-running operations
  • Avoid RA Run Analysis during testing — the ~100s run blocks Flask and can drop the MCP connection

Known Limitations

  • MCP connection can drop during long RA runs. Reconnect with tabs_context_mcp(createIfEmpty=True)
  • Programmatic KeyboardEvent dispatch doesn't trigger shortcut handlers — use computer(action='type') instead
  • The #main div is the scroll container — document.getElementById('main').scrollTop gives the true scroll position
