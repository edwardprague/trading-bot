1 · Backtesting

🔗
localhost:8080/

The iteration workbench. The active version's parameters drive every run — instrument, interval, direction, EMA, stop loss, RRR, blocked hours, and regime gates are all fixed by the version. The only user input is the date range.

ℹ️
P&L note: Sub-period runs start from $100k equity, not the compounded equity of the parent run. Trade counts and win rates are accurate; dollar P&L will differ. Use the parent run's Monthly / Daily tables to read accurate sub-period P&L — don't re-run to check.

Micro Regime Detection

Fractal Parameters

On the Backtesting page, for date runs under 1 month, we have a Fractals table tracking the following information for each fractal.

Each confirmed N=2 fractal records a set of real-time metrics. These are available at the moment the fractal forms — no look-ahead required — and are displayed in the Backtesting fractal table.

Column What it measures What it shows
Type Upper fractal or lower fractal Upper and lower
L# Micro trend leg number The number of lower fractals before a higher fractal forms. Each of those H fractals gets a number.
H1 1 fractal Current swing size in pips — the raw leg just completed
H3 Last 3 fractals Short moving average of swing size
H6 Last 6 fractals Medium moving average of swing size
ADX Trend strength at the time of the fractal — not direction, but conviction High ADX confirms a genuine trend; low ADX suggests ranging regardless of fractal direction
ATR (pips) Average true range — current volatility in pips Context for stop sizing and swing expectations
VD High / Low Vertical displacement — net pip movement since the prior fractal of the same kind Indicates whether swing highs or lows are expanding or compressing
Pullback % How far price retraced before confirming the fractal, as a percentage of the prior swing Shallow pullbacks in a downtrend suggest strong momentum; deep pullbacks suggest hesitation

Swing Height — H1, H3, H6

The pip distance from the current fractal's price to the most recent opposite-kind fractal (e.g. for a high-fractal: distance to the nearest prior low-fractal). H1 is the raw value; H3 and H6 are rolling means over the last 3 and 6 non-null heights respectively, forming a smoothing ladder over the same underlying series.

H Combinations

H1 > H3 > H6
Expansion
Swings are expanding — momentum accelerating
H1 < H3 < H6
Contraction
Swings are contracting — momentum fading or exhaustion
H1 ≈ H3 ≈ H6
Neutral
Swings are stable — consistent rhythm

The micro gate answers: is the immediate intraday fractal structure aligned with the trade direction? It tracks the last 4 high-fractals and last 4 low-fractals continuously, classifying the current market character in real time.

Label Description
trending_fast/medium/slow_down Both highs and lows making consistent lower-high / lower-low sequence, graded by speed
ranging_narrow/medium/wide No clear directional sequence — market oscillating, graded by range width
transitioning Regime in flux — insufficient consecutive same-kind fractals to confirm a new state
trending_fast/medium/slow_up Both highs and lows making consistent higher-high / higher-low sequence

The micro classifier uses a state machine — it does not reset at midnight. It carries fractal state continuously, which gives it natural persistence across day boundaries and makes it genuinely live-capable without modification.

Fine sub-labels (fast/medium/slow, narrow/medium/wide) are computed using four frozen threshold constants derived from training data:

Constant Value Used for
pips_per_bar_t1 0.7249 Trending slow / medium boundary
pips_per_bar_t2 1.3061 Trending medium / fast boundary
width_pips_t1 10.875 Ranging narrow / medium boundary
width_pips_t2 18.118 Ranging medium / wide boundary

Macro Regime Detection

Fractal Height + ADX

The macro gate answers: is the market in an active, directional state right now? It is computed at each N=2 fractal formation using two signals that are available natively in real time.

Signal What it measures Gate threshold
H1 — current swing height Size of the most recent fractal leg in pips. Large swings indicate the market is making decisive moves. H1 ≥ T_height (default 10 pips)
ADX-14 — trend strength Directional conviction — not direction itself, but whether price is moving with purpose rather than ranging. ADX ≥ T_adx (default 20)

2 · Regimes

🔗
localhost:8080/results/regime_analysis.html

The diagnostic lens. Breaks the active version's behaviour down by market regime — both day-level (macro) and intraday (micro). Always uses the active version — no version dropdown.

⚠️
RA does not auto-run on load. Results shown are from the last saved run. Click Run Analysis to refresh (~30–100s, blocks Flask). Avoid triggering during browser testing.

3 · Discovery

🔗
localhost:8080/discovery

The optimisation engine. Explores the parameter space via random search, running a full backtest for each trial and scoring against the passing criteria. Each run is independent — random seed, no pooling across runs.

💡
Seed: Leave as "random" for exploration. Note the seed if you need to reproduce a specific run exactly. Currently the seed is not stored in run results — a known gap to fix.

4 · Versions

🔗
localhost:8080/versions

The lifecycle manager. Each version is a named profile bundling a set of Discovery-assigned parameters and its own regime allow-list state. The active version drives all BD backtests and RA runs.

  • Radio buttons — selecting sets that version as active immediately, persists to data/versions.json
  • Version numbering — sequential, auto-renumbers on deletion. New additions always increment from highest existing number.
  • Add Version — creates the next vN as an unassigned slot. Parameters are filled by assigning a Discovery trial.
  • Notes field — free-form per version, auto-saves on blur
  • Delete — removes version and triggers live rekey of versions.json, run buckets, and Discovery assignment records
⚠️
data/versions.json is the source of truth. Always commit to git after version changes.
Dashboard Workflow
1

Run Discovery

Set instrument, interval, direction, blocked hours. Run 200+ trials over a training window. Review passing trials sorted by PF.

2

Assign to Version

Click Assign on a promising trial. This creates a version profile with all parameters locked. data/versions.json is the source of truth — commit after changes.

3

Validate on BD (out-of-sample)

Run the version on a date range Discovery never saw. Check whether numbers degrade gracefully or collapse. Accurate P&L — don't re-run sub-periods, read from the parent run's tables.

4

Confirm on RA

Check that regime gates make intuitive sense on the out-of-sample window. Are the blocked regimes genuinely bad, or overfitting to training noise?

5

Generate cBot & Forward Test

Click Create cBot on the BD. Copy FractalBot_v{N}.cs into cTrader. Run on live data. Edit logic in cbot_templates.py, not the generated file.
