Dashboard Workflow
1

Run Discovery

Set instrument, interval, direction, blocked hours. Run 200+ trials over a training window. Review passing trials sorted by PF.

2

Assign to Version

Click Assign on a promising trial. This creates a version profile with all parameters locked. data/versions.json is the source of truth — commit after changes.

3

Validate on BD (out-of-sample)

Run the version on a date range Discovery never saw. Check whether numbers degrade gracefully or collapse. Accurate P&L — don't re-run sub-periods, read from the parent run's tables.

4

Confirm on RA

Check that regime gates make intuitive sense on the out-of-sample window. Are the blocked regimes genuinely bad, or overfitting to training noise?

5

Generate cBot & Forward Test

Click Create cBot on the BD. Copy FractalBot_v{N}.cs into cTrader. Run on live data. Edit logic in cbot_templates.py, not the generated file.

1 · Backtesting (BD)

🔗
localhost:8080/

The iteration workbench. The active version's parameters drive every run — instrument, interval, direction, EMA, stop loss, RRR, blocked hours, and regime gates are all fixed by the version. The only user input is the date range.

Element Description
Run bar Date pickers + Add Year / Add Date Range buttons. Progress indicator shows Sending → Running backtest → Building report.
Active version Shown top-right at all times. Set on the Versions page.
Title row Shows version · instrument · interval · date range e.g. v1 · GBPUSD · 5m · Jul-01-25 → Dec-31-25
Sidebar All saved runs for the active version, grouped by Year / Month / Weeks / Day. Hover a run to reveal the eye icon → chart preview.
Report area Results panel (net profit, win rate, PF, drawdown) + Parameters panel. General / Advanced tabs.
Backtest Settings Collapsible. Shows active version parameters. "Restore to version defaults" appears when values differ.
Clickable dates Every date range in every table (except Intraday Performance) is clickable — inserts that range into the run bar.
ℹ️
P&L note: Sub-period runs start from $100k equity, not the compounded equity of the parent run. Trade counts and win rates are accurate; dollar P&L will differ. Use the parent run's Monthly / Daily tables to read accurate sub-period P&L — don't re-run to check.

2 · Regimes (RA)

🔗
localhost:8080/results/regime_analysis.html

The diagnostic lens. Breaks the active version's behaviour down by market regime — both day-level (macro) and intraday (micro). Always uses the active version — no version dropdown.

Macro Regimes 5
  • Strong Down — sharp directional fall
  • Staircase Down — stepped decline
  • Flat — no clear direction
  • Staircase Up — stepped rise
  • Strong Up — sharp directional rise
Micro Regimes 10
  • Trending Fast / Medium / Slow Down
  • Trending Fast / Medium / Slow Up
  • Ranging Narrow / Medium / Wide
  • Transitioning
⚠️
RA does not auto-run on load. Results shown are from the last saved run. Click Run Analysis to refresh (~30–100s, blocks Flask). Avoid triggering during browser testing.

3 · Discovery

🔗
localhost:8080/discovery

The optimisation engine. Explores the parameter space via random search, running a full backtest for each trial and scoring against the passing criteria. Each run is independent — random seed, no pooling across runs.

Setting Type Detail
Instrument Fixed · Editable GBPUSD or EURUSD (and new pairs)
Interval Fixed · Editable Bar interval — set per run, not randomised
Direction Fixed · Editable Both / Long Only / Short Only
Blocked Hours Fixed · Editable UTC hours excluded from entries (pill UI)
Slippage Fixed · Read-only On — 1 pip SL + 1 pip spread
EMA Long Searched 10 – 200
Stop Loss Searched 5 – 50 pips
RRR Reward Searched 1 – 5 (risk fixed at 1)
Max DD Searched 1 – 5
EMA Filter Searched On / Off
Macro Regimes Searched Any combination of 5
Micro Regimes Searched Any combination of 10
Profit Factor Passing Criteria ≥ 1.5 (editable)
Min Trades Passing Criteria Editable — scale with date range
Max Drawdown Passing Criteria ≤ 15% (editable)
💡
Seed: Leave as "random" for exploration. Note the seed if you need to reproduce a specific run exactly. Currently the seed is not stored in run results — a known gap to fix.

4 · Versions

🔗
localhost:8080/versions

The lifecycle manager. Each version is a named profile bundling a set of Discovery-assigned parameters and its own regime allow-list state. The active version drives all BD backtests and RA runs.

  • Radio buttons — selecting sets that version as active immediately, persists to data/versions.json
  • Version numbering — sequential, auto-renumbers on deletion. New additions always increment from highest existing number.
  • Add Version — creates the next vN as an unassigned slot. Parameters are filled by assigning a Discovery trial.
  • Notes field — free-form per version, auto-saves on blur
  • Delete — removes version and triggers live rekey of versions.json, run buckets, and Discovery assignment records
⚠️
data/versions.json is the source of truth. Always commit to git after version changes.
