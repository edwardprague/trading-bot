Team Workflow Responsibilities

Ada's Workflow - As Strategy Analyst

  • Leads the research agenda. Forms hypotheses, runs analyses, interprets results, proposes next steps. Works autonomously within the current strategic priority.
  • Surfaces genuine decision points — findings with strategic implications, trade-offs between directions, results that change the picture significantly. Presents options with honest assessment of each, not just "what should I do next?"

Ada's Workflow - As Developer

  • Ada receives tasks and implements them.
  • Always ask clarifying questions if the request is ambiguous.
  • New styling goes in style.css — never use inline style="…" attributes on new HTML.
  • When a task is done, state what Edward needs to do to see the change:
  • Restart the Flask server (needed for server.py changes including INJECT_HTML)
  • Run a backtest from the dashboard to regenerate report.html (only if a strategy-template change should be visible immediately)
  • Run python3 regime_analysis.py to regenerate results/regime_analysis.html (RA page changes only)
  • Or any combination of the above.
  • In-browser verification. Visual and event-flow bugs must be verified in a real browser via Claude in Chrome, not just sandbox-tested.

Chat's Workflow

  • Edward and Chat discuss results and suggestions from Ada and guide research and development. After deciding on specific instructions for Ada, Chat will summarize the instructions and Edward will relay them.
  • Chat will almost always need to view the dashboard in the browser for reference and testing, and should make sure to be connected.

Trade Entry Gate Pipeline Order

The first gate that rejects a signal stamps a reason on it, driving counterfactual stats in the RA.

1

Signal generation

Fractal detection + higher-low / lower-high test

2

Direction filter

TRADE_DIRECTION — both / long_only / short_only

3

EMA position filter

v2 only, if USE_EMA_FILTER is on

4

Daily loss limit

Blocks entries once MAX_DAILY_LOSSES is reached for the UTC day

5

Time filter

BLOCKED_HOURS_UTC

6

Macro regime gate

7

Micro regime gate

8

Stop-distance validation

MIN_STOP / MAX_STOP range check

9

Trade execution

Signal accepted — position opened

cTrader Integration
Code Generation

Click Create cBot on the BD. This calls cbot_templates.py which renders FractalBot_v{N}.cs. The generated file is overwritten on every generation — never edit it directly. All logic changes go in cbot_templates.py.

ℹ️
C# runs natively inside cTrader as a cBot. The Python Open API is an external connection not suitable for prop firm use.
