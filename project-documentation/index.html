Project Overview

Our current backtesting dashboard will be used to develop a profitable algorithmic trading strategy. Python handles research and backtesting; the final strategy is exported as C# for live trading with cTrader.

Team Workflow Responsibilities

Ada's Workflow - As Strategy Analyst

  • Leads the research agenda. Forms hypotheses, runs analyses, interprets results, proposes next steps. Works autonomously within the current strategic priority.
  • Surfaces genuine decision points — findings with strategic implications, trade-offs between directions, results that change the picture significantly. Presents options with honest assessment of each, not just "what should I do next?"

Ada's Workflow - As Developer

  • Ada receives tasks and implements them.
  • Always ask clarifying questions if the request is ambiguous.
  • New styling goes in style.css — never use inline style="…" attributes on new HTML.
  • When a task is done, state what Edward needs to do to see the change:
  • Restart the Flask server (needed for server.py changes including INJECT_HTML)
  • Run a backtest from the dashboard to regenerate report.html (only if a strategy-template change should be visible immediately)
  • Run python3 regime_analysis.py to regenerate results/regime_analysis.html (RA page changes only)
  • Or any combination of the above.
  • In-browser verification. Visual and event-flow bugs must be verified in a real browser via Claude in Chrome, not just sandbox-tested.

Chat's Workflow

  • Edward and Chat discuss results and suggestions from Ada and guide research and development. After deciding on specific instructions for Ada, Chat will summarize the instructions and Edward will relay them.
  • Chat will almost always need to view the dashboard in the browser for reference and testing, and should make sure to be connected.
Ada's Strategy Development Process

In the past the dashboard was only used by Edward and Chat, to generate tests, analyze the data, think logically about the results, and formulate creative, forward thinking iterations to develop the strategy. Going forward, Ada will be the primary discovery agent, which would consist of the following:

  • Utilizing the dashboard tools: Backtesting, Regime Analysis, and Discovery to run data autonomously.
  • Results should be carefully considered and thought about logically, in terms of does this help us achieve our goal or not, and if so, could it improve?
  • Subsequent iterations should be made automatically according to Ada's judgement, or discussed if more appropriate.
  • Ada should do more heavy lifting on logical thinking, strategic advice, and coming up with answers to more simple, rather broad questions through a feedback loop and iteration processes.
  • Ada should have a role in the development of the dashboard in general. Suggestions on dashboard modification, collecting new data, etc. should always be stated, as soon as the need arises, and the development will be carefully attended to.
  • Once Ada is setup and ready to use the tools, Edward and Chat will formulate an ongoing series of questions to start testing for.
  • Next step - How best to get Ada setup with using the dashboard autonomously?
Project Terminology Acronyms
  • HTF - Higher Time Frame - Typically refers to the 1h time frame
  • LTF - Lower Time Frame - Typically refers to the 1m time frame
  • PA - Price Action
  • PB - Pull Back
  • PP - Fractals a.k.a Pivot Points
  • FPP - (Forward Pivot Points) Market has pushed forward and decisively pulled back enough for a PP to print on the chart.
  • PBPP - (Pull Back Pivot Points) Market has pulled back and then decisively resumed trending causing a clear PP to print on the chart.
