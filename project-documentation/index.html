Project Overview

A backtesting dashboard for developing an algorithmic trading bot for cTrader. Python handles research and backtesting; the final strategy is exported as C# for live trading.

Manages overall direction. Decides what gets built next, reviews results, and bridges between Chat and Ada.

Cowork (Ada)
Implementation

Team Workflow Responsibilities

Ongoing Docs Maintenance (Chat / Ada)

  • At significant milestones in each chat we'll be updating the docs, located in the project-documentation directory or URL http://localhost:8080/docs/index.html
  • Ada should update the docs directly in the file, and Chat should provide code snippets in the chat window for copy and paste.

Instructions to Ada from Chat

  • After Edward and Chat decide on instructions for Ada, Chat will summarize the instructions and Edward will relay them.
  • When Chat gives instructions to Edward for Ada to execute, the instructions should be in a single paragraph block of text, in italics.

Ada's Workflow

  • Development is task-driven — Receiving tasks, then implementing them.
  • Always ask clarifying questions if the request is ambiguous.
  • New styling goes in style.css — never use inline style="…" attributes on new HTML.
  • When a task is done, state what Edward needs to do to see the change:
  • Restart the Flask server (needed for server.py changes including INJECT_HTML)
  • Run a backtest from the dashboard to regenerate report.html (only if a strategy-template change should be visible immediately)
  • Run python3 regime_analysis.py to regenerate results/regime_analysis.html (RA page changes only)
  • Or any combination of the above.
  • In-browser verification. Visual and event-flow bugs must be verified in a real browser via Claude in Chrome, not just sandbox-tested.
